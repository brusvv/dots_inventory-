# Первоначальная установка Dots Inventory из GitHub без clasp

## Назначение

Этот способ предназначен для первоначальной установки на **новую тестовую Google-таблицу** без локальной копии репозитория, Node.js, Git или clasp.

Одно ручное действие всё равно необходимо: скопировать один Bootstrap-файл из GitHub в редактор Apps Script. До этого в проекте ещё нет кода, который мог бы скачать и установить остальные модули.

После первоначальной установки штатные проверки, Preview-обновления, резервное копирование и откат выполняются из меню самой таблицы.

## Ограничения и безопасность

- Bootstrap закреплён за commit `39ae1b1af9753a31ab3c92175d5fe6d33ef92f16`; он не скачивает код с движущейся ветки.
- В этом commit находится ровно 47 файлов `.gs` в `src/apps_script/`.
- Каждый исходник проверяется по Git blob SHA-1 и размеру из Git tree до записи в проект.
- До записи создаётся резервная копия полного текущего Apps Script source, включая `appsscript.json`; файл повторно читается, проверяются SHA-256 каждого файла и общая контрольная сумма. Формат совместим с D-04/D-06 source backup.
- Перед записью показывается YES/NO подтверждение. После подтверждения проект повторно читается для защиты от параллельных изменений.
- После записи весь проект повторно читается и сверяется с целевым набором.
- Установка кода не запускает setup, Clean Start, миграцию схемы, FIFO, импорт, восстановление или складские операции.
- Bootstrap допускает только `appsscript.json`, собственный файл `DI3_GitHubBootstrap.gs` и пустой стандартный `Code.gs`. Любые другие файлы блокируют установку; они не удаляются автоматически.
- Рабочая RC8-таблица не подходит для проверки чистой схемы v4. Используй новую отдельную тестовую таблицу и отдельный Script ID.
- Никакие Git-теги, GitHub Releases, PR merge или production deployment этим способом не создаются.

## Шаг 1. Создать тестовую таблицу и Apps Script-проект

1. Создай новую Google Sheets таблицу. Не используй рабочую RC8 и не делай установку в её Script ID.
2. Открой **Расширения → Apps Script**.
3. В настройках проекта включи отображение файла манифеста `appsscript.json`.
4. Убедись, что проект привязан к новой таблице. Bootstrap дополнительно проверит наличие активной таблицы.
5. Не добавляй в проект другие модули или HTML-файлы.

## Шаг 2. Подготовить манифест и разрешения

В файле `appsscript.json` сохрани существующие поля и добавь/проверь следующие значения. Для совершенно нового проекта пример полного манифеста:

```json
{
  "timeZone": "Europe/Moscow",
  "dependencies": {},
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/script.projects",
    "https://www.googleapis.com/auth/script.projects.readonly",
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/drive",
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/script.container.ui",
    "https://www.googleapis.com/auth/script.scriptapp"
  ]
}
```

Не заменяй манифест существующего проекта этим примером целиком: сохраняй его индивидуальные настройки. Для новой тестовой таблицы часовой пояс должен быть `Europe/Moscow`, как в `DI3_APP_CONFIG.TIME_ZONE`.

В Google Cloud Console проекта, связанного с Apps Script, включи **Google Apps Script API**. Если Apps Script предлагает связать проект со стандартным Google Cloud project, выполни это для тестового проекта и включи API там.

## Шаг 3. Добавить Bootstrap из GitHub

1. Открой [bootstrap/DI3_GitHubBootstrap.gs в feature/github-browser-bootstrap](https://github.com/brusvv/dots_inventory-/blob/feature/github-browser-bootstrap/bootstrap/DI3_GitHubBootstrap.gs).
2. Скопируй весь файл.
3. В редакторе Apps Script создай файл с точным именем `DI3_GitHubBootstrap.gs`.
4. Вставь код, сохрани проект.
5. Убедись, что имя функции `di3GitHubBootstrapInstall` отображается в списке функций.

Не копируй этот файл в рабочий проект. Ветку и commit, закреплённые внутри Bootstrap, не меняй вручную.

## Шаг 4. Запустить первоначальную установку

1. Выбери функцию `di3GitHubBootstrapInstall`.
2. Нажми **Выполнить**.
3. При первом запуске выдай разрешения Google для текущего тестового проекта.
4. Bootstrap проверит Script ID, привязку к таблице, состав проекта, манифест, scopes, GitHub tree и все 47 исходников.
5. Он создаст и проверит Drive backup.
6. В диалоге установки проверь таблицу, Script ID, commit, число модулей и ссылку на backup.
7. Только если всё соответствует ожиданиям, нажми **Yes**. Кнопка **No** завершает запуск без записи кода.

Если проверка не пройдена, функция остановится до `projects.updateContent`. Не удаляй проверки и не обходи блокировку — сначала исправь причину.

## Шаг 5. Проверить результат

Успешный результат должен иметь статус `INSTALLED_AND_VERIFIED`. Bootstrap повторно читает Apps Script project content и сравнивает полный набор файлов.

Затем:

1. Вернись в Google Sheets и перезагрузи страницу.
2. Проверь, что появилось меню Dots Inventory.
3. Не запускай Clean Start, миграции, импорт, восстановление или операции со складом.
4. Сохрани ссылку и ID созданного source backup. Этот backup имеет формат D-04 и может использоваться штатным D-06 rollback после установки модулей GitHub-менеджера.
5. Выполняй runtime-приёмку только по `docs/GITHUB_RUNTIME_ACCEPTANCE.md` и только в этой тестовой таблице.

## Что будет после установки

В проекте остаётся `DI3_GitHubBootstrap.gs` как отдельный вспомогательный модуль; штатный release manifest не содержит его, поэтому updater должен сохранять его как локальный unmanaged SERVER_JS файл.

Штатный менеджер обновлений использует опубликованные GitHub Releases. На момент подготовки Bootstrap опубликованного Preview/Stable релиза ещё нет. Поэтому команда проверки релиза может вернуть `NO_RELEASE` — это ожидаемо, а не ошибка первоначальной установки. Не создавай tag/release до отдельного решения о публикации Preview.

Для теста Preview позже нужно будет явно выбрать `RELEASE_CHANNEL = "preview"` в `00_DI3_AppConfig.gs` тестового проекта и опубликовать соответствующий Preview-релиз. Рабочий проект и Stable-канал остаются без изменений.

## Что Bootstrap не делает

- Не устанавливает приложение в production.
- Не меняет данные Google Sheets.
- Не запускает setup или миграции.
- Не создаёт триггеры и не публикует deployment.
- Не переключает канал Stable/Preview.
- Не создаёт GitHub tag или Release.
- Не устанавливает будущие обновления автоматически; для них используется штатный менеджер обновлений.
