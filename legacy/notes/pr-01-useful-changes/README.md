Это архивная копия трёх полезных замечаний из PR #1. Файлы не подключаются к Apps Script-проекту автоматически и не меняют активный код ветки.

## 1. Исправление сброса времени исторической продажи

Историческая форма использует актуальные поля времени `C5:C6`, а старые поля — `D5:D6`.
После успешного сохранения очищаются оба диапазона:
- `C5:C6` — действующие поля времени, чтобы следующая продажа не унаследовала прошлые значения;
- `D5:D6` — защитная очистка устаревших полей.

Очистка должна происходить только после успешного вызова `di3CreateHistoricalSale(command)`. Ветку отмены/ответа NO нельзя очищать как успешное сохранение.

Архив исходного файла: `17_DI3_OrderWorkspace.gs`.

## 2. Регрессионная проверка сброса формы

В `40_DI3_CatalogOrderUxTests.gs` добавлена проверка порядка выполнения:
- создание исторической продажи должно произойти раньше очистки;
- очищаются текущие поля `C5:C6`;
- очищаются устаревшие поля `D5:D6`;
- отмена/NO завершается до создания и не должна выполнять успешный сброс.

Архив исходного файла: `40_DI3_CatalogOrderUxTests.gs`.

## 3. Диагностика графика Warehouse Dashboard

В меню склада добавлен read-only пункт:
- название: «Диагностика диаграммы Dashboard (без изменений)»;
- обработчик: `di3LogWarehouseDashboardChartDiagnostics`;
- результат диагностики выводится в Apps Script execution log;
- команда предназначена для диагностики конфигурации/данных диаграммы без изменения таблицы.

Архив соответствующего исходного участка меню/диагностики: см. `warehouse-dashboard-diagnostics.md` и существующие пробы в `legacy/tests/warehouse-dashboard/`.
